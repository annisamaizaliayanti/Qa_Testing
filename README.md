# StrongHeron QA — How to Test

This is the entry point for anyone performing QA testing on StrongHeron. Follow the phase order below, use the two live apps listed, and record results in the **QA Test Case Summary** table in each `PHASE_*.md` file.

---

## 1. App Links

| App | URL | Used by |
|---|---|---|
| **Admin (Web)** | https://strongheron-react.vercel.app/ | Admin, Owner, Dispatcher — setup, quotes, invoices, dispatch, approvals |
| **PWA (Mobile)** | https://strongheron-pwa-mobile.vercel.app/ | Technician / Owner mobile — job execution, checklist, time, checkout in the field |

> Open the PWA in a mobile browser (or Chrome DevTools device mode) for the closest experience to a real tech in the field. The PWA can also be "Added to Home Screen" to simulate installing it as an app.

---

## 2. Login

### Admin (Web)
1. Open https://strongheron-react.vercel.app/login
2. Enter admin email + password (see credentials from team / Phase 1 — Admin Login).
3. Successful login → redirects to `/dashboard`.

### PWA (Mobile)
1. Open https://strongheron-pwa-mobile.vercel.app/login
2. Enter technician email + password (created/invited via Admin → Team, see Phase 1 — Invite Technician).
3. Successful login → redirects to `/today` (My Day).

If you don't have a technician account yet, create one via Admin → Team → Invite, then accept the invite (see [PHASE_1_SETUP_ONBOARDING.md](PHASE_1_SETUP_ONBOARDING.md)).

## 4. How to Record Results

Each `PHASE_*.md` file has a **QA Test Case Summary** table at the top:

| User Story | Test Scenario | Test Step | Result | Status |
|---|---|---|---|---|

- **Test Scenario / Test Step / Result** are pre-filled based on feature design.
- **Status** is intentionally blank — fill it in during testing with one of:
  - `✅ Pass` — behaved as described in Result
  - `❌ Fail` — did not match, write a short bug note in the same cell
  - `— N/A` — not applicable in this environment
  - `☐ Pending` — not yet tested

Detailed step instructions (more granular Action/Test Step including example form data) are in the lower section of each file, under the `## Step X.YY` headings.

---

## 5. General Notes

- The Customer Portal (quote/invoice approval) is accessed via the `/p/:token` link sent to the customer when a quote/invoice is *sent* — it is not a separate URL; always open it from the link generated by the system.
- Data across phases is interconnected (`created_from` chain) — do not delete data from earlier phases when moving to the next.
- If you want to reset and test from scratch, start again from [PHASE_1_SETUP_ONBOARDING.md](PHASE_1_SETUP_ONBOARDING.md) with a new company/customer so it does not conflict with previous test data.
